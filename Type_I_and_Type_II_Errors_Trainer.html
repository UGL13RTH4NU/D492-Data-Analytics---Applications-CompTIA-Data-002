SAID / WAS shortcut
  • SAID YES, WAS NO → Type I (false alarm)
  • SAID NO, WAS YES → Type II (missed it)
  • SAID = WAS → Correct, no error

SAID = what the test claimed. WAS = ground truth in the scenario.

Courtroom analogy
  • H₀: "The defendant is innocent" (status quo)
  • Type I: Convict an innocent person (rejected true null)
  • Type II: Acquit a guilty person (accepted false null)
Cybersecurity mapping
  • Type I / FP: IDS alerts on benign traffic → alert fatigue
  • Type II / FN: IDS misses real intrusion → breach
  • Spam filter: FP = real email flagged; FN = phish gets through
  • AV: FP = flags legit software; FN = lets malware run
How to reduce each error
  • Reduce Type II: ↑ sample size (n), ↑ statistical power, better study design
  • Reduce Type I: ↓ α threshold (e.g., .05 → .01), correct for multiple comparisons
  • Tradeoff: Reducing one usually increases the other. You can't minimize both simultaneously.
Which error is worse?
  • Depends on the domain and cost of each mistake.
  • US criminal law: Type I > Type II (better guilty walk than innocent imprisoned)
  • Cancer screening: Type II > Type I (better false alarm than missed diagnosis)
  • Airport security: usually Type II > Type I
  • Drug approval: usually Type I > Type II (don't approve ineffective/harmful drugs)
Memory hooks
  • Type 1 = convict the 1nnocent (rejected truth)
  • Type 2 = 2o late to catch the guilty (missed the real one)
  • "False" describes what the TEST said, not reality
  • α before β; Type I before Type II — the α/Type I error is what we control first with the significance level
